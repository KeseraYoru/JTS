## ★ 关键发现：valid → 平台的落差是稳定的 −0.0295
| 版本 | 本地 valid | 平台 | 落差 |
|---|---|---|---|
| 旧（非合规 EVA-X+CheXFound 集成） | 0.8240 | 79.36 | +0.0304 |
| 新（合规 ConvNeXt soup） | 0.7977 | 76.91 | +0.0286 |

两个模型、两套架构、两种合规状态，落差却几乎相同（0.029~0.030）。
→ **结论：这不是模型 bug，是「官方 test 比 valid 系统性更难」（时间/设备/人群差异）。**
→ 由此得到可用的换算公式：**平台分 ≈ valid − 0.0295**，可直接用来预测每次提交的回分。
→ 反推目标：要追平旧分 79.36，**valid 必须达到 0.8231**；当前 0.7977，差 **+0.0254**。

## 现状定位

- 旧提交本就违规需撤销，所以真实基线是 76.91，而不是 79.36。

## 下一步提分路线（按「性价比 × 确定性」排序）
1. **分辨率 384 → 448**（最高确定性）：EVA-X 当年就用 448；胸片靠细节，384 把 3000px 压了 8 倍。
   成本 1 seed ≈ 50min。判据：valid 提升 ≥0.008 就值得铺开 3 seed。
2. **SSL 从 20 epoch → 150+ epoch**（最高上限）：SimCLR 20 轮远远不够「学会」，
   但已足够「改写」特征（check_backbone 测得改动幅度 1.259）。合规前提下这是唯一能补「医学域先验」
   的手段，值得再投 2~3 小时。
3. **罕见类专项**：类 1/2/3（894/1238/1265 正样本）AUC 仅 0.68/0.83/0.78，是 Macro 的最大洼地；
   类 1 从 0.68 → 0.75 就等于 +0.007 macro。手段：类别平衡采样 / 提高这几类 pos_weight 上限 / 更强增强。
4. **全量重训（train+valid）+ 蒸馏**：+0.003~0.008，且蒸馏能把 3-seed 预测级集成压进单模型（334MB）。
5. **（可选，风险高）fp16 双架构集成**：convnext_base fp16 ≈167MB + swin_b fp16 ≈167MB = 334MB，
   预测级集成仍在 500MB 内，且 fp16 推理更快有利于 100ms 限制。但工程复杂度高。

## 现实预期
把 1~4 全做上，valid 乐观 0.825~0.835 → 平台 79.5~80.5；保守 0.815 → 78.5。
即「合规版最终与旧违规分基本持平或略好」。要显著突破需靠 SSL 质量与更高分辨率。

## ★ cost.py 首次实测通过（10-31 11:24）——合规链路全部打通
- 环境：5090，convnext_base @384px，fp16 AMP，无 TTA，batch=1 串行，100 张 × 3 轮。
- **结果：单张端到端 16 ms（三轮 16.8 / 17.1 / 13.7），与 submission.csv 不一致 0 张。**
- 意义：① 第 7 条耗时核验达标且余量巨大；② 一致性 0 张 → predict.py 与 cost.py 共用
  inference.py 的设计有效，复赛核验不会挂；③ 「合规三件套」(cost.py / check_compliance / make_package)
  现在全部经过真实验证。
- **换算到复赛 T4**（fp16 算力约 1/3.5~1/4）：384px ≈ 48~64ms；448px ≈ 65~87ms；512px ≈ 85~114ms。
  → **448 是安全甜点**，512 有超限风险（复测只给一次整改机会）。
- 权重预算：当前 350MB（余 150MB）；若存 fp16 只需 175MB，可腾 175MB；
  convnext_large fp16 = 396MB 虽能进 500MB，但算力约 2.3 倍，T4 上会撞 100ms → 不划算。
- 结论：**分辨率往上加几乎不花时间成本**，448 应作为默认；帧内还够跑 2~3 个 TTA（但 TTA 只值 +0.001，不做）。
