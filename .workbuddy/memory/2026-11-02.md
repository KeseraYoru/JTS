- **写手册时发现 4 个计划文档里没暴露的工程缺口**（落地前必须解决）：
  1. `preprocess.py` **没有 `--size` 参数**，尺寸写死在 `config.PREP_SIZE=600` → 出 1024² 必须先改代码
     （加 `--size`，并把 size 塞进 `_resize_one` 的任务元组）。
  2. `predict.py` **只支持 `--split valid|test`，没有 `--csv`** → 无法对「某折验证集」出预测
     → **OOF 和蒸馏都做不了**。必须加 `--csv`，且 `--split` 的 choices 增加 `"train"`。
  3. 加融合模块后 ckpt 键会变，`inference.py` 用 `build_model(backbone)` 重建会报 unexpected keys
     → ckpt 必须写 `arch` 字段、inference 读它。（A1 的隐藏成本）
  4. **蒸馏软标签必须用 OOF**（每行由没见过它的折模型预测），否则教师在自己见过的图上过度自信，
     学生只是背答案。这是方法正确性问题，不是优化。
- 消融优先级已修正为：**A5(512) → A3a(多尺度裁剪) → A2(强增强) → A1(融合) → A4(排序损失)**。
  理由：融合与 512 解决同一问题（细节丢失），512 更直接；若 512 过门，A1 边际收益缩水。
- A3 落地方式澄清：无法硬编码解剖 ROI 坐标，实际实现为「从 1024² 源图 RandomResizedCrop(0.35~1.0)」
  即随机 ROI/多尺度采样，配 FixRes（测试分辨率略高）补偿 train-test 分布差。

## 服务器实测（12:00）
- 冒烟：`ssl_pretrain.py --epochs 1 --limit 2000` → **20s / 3 step**（batch 128×4=512，drop_last），
  loss 3.7010（正常：骨干已是 ImageNet，NT-Xent 起点远低于 ln(1024)）。
- **20s 不能直接外推**：2000 张只有 3 个 step，其中 10~15s 是启动开销（建模型/载权重/起 worker/预热）。
  实际全量单轮可能在 2.7~5 min 之间，差一倍 → 必须用 `--epochs 3 --limit 12000` 读第 2、3 轮。
- **事故：旧的 20 epoch SSL 权重被覆盖**。`--out` 默认 `runs/ssl/ssl_backbone.pth`，冒烟没带 `--out`
  → 直接用 2000 张 1 轮的权重盖掉了（实测该文件 350MB = 87.6M 参数 fp32，即 backbone 全量）。
  处理决定：**不重建**。20ep 的唯一用途是探针基准，而它的历史读数已有（@384 probe ep2 = 0.7718），
  且用「ImageNet 起点 vs SimCLR 200ep」直接比较更有意义（回答"加长 SSL 到底有没有用"）。
  **G1 判据随之修正：200ep 需比 ImageNet 起点高 >0.008**（20ep 历史只高 0.007）。
- 铁律：任何冒烟必须带 `--out runs/ssl/_smoke.pth`，默认值只留给正式训练。
- **DINO 成本重估**：多裁剪 8 视图 ≈ SimCLR(2视图) 的 3.5 倍 → 若 SimCLR 200ep 是 10h，DINO 就是 35h。
  倾向：**DINO 退回加练**，主线用 SimCLR 加长版（收益区间重叠但便宜 3.5 倍）。

- 448 + batch 128 **OOM**（每卡 32 张 × 2 个视图的计算图同留 = 30GB↑）。教训：改分辨率必须同步改 batch。

  这解释了 10-31 那个 16ms：当时 pictures_100 只能用 data600 副本凑。
