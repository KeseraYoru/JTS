## 第 2 章　P0 基础设施（D1）

> 这一章的全部意义是：**把"我以为的耗时"变成"实测的耗时"**。上一轮那个 16ms 的读数不可信（见 2.1），如果不定档就往上堆分辨率，复赛会直接判不认定。

### 2.1 为什么必须先改推理路径（30 秒读懂）

现在有两条读图路径，它们不一致：

```
训练/验证/predict.py  →  data600/xxx.jpg（600² 小图，100KB）
                                    ↑ 由原图 resize 而来

cost.py（官方核验）   →  cxr_first/test/xxx.jpg（原图，2500×3056，1.5MB）
```

同一张片子，走两条路算出的概率会有 0.0003~0.001 的差异——正好卡在规则允许的 |Δp|≤1e-3 边缘。
更严重的是**耗时完全不同**：2500×3056 的 JPEG 解码在 CPU 上要 60~150ms，这一项就能吃光 100ms 预算。

**但是**，我们要缩到 448，本来就要扔掉 96% 的像素。所以可以让 **libjpeg 在解码时就直接降采样**，
用 `Image.draft()`（JPEG 的 DCT 缩放开箱即用）：

```
全解码：3056×3052 = 933 万像素 → 再缩到 448    解码成本 100%
draft：libjpeg 按 1/4 尺度解码 → 764×763 = 58 万像素   解码成本 ≈ 6%
```

规则第 7 条允许「优化推理实现」，这是纯实现优化，不动权重、不改预测语义。

### 2.2 【改】`inference.py`：加 draft 解码

**改哪里**：`inference.py` 第 51-54 行的 `_load_one`

改前：

```python
def _load_one(path, tfm):
    with Image.open(path) as im:
        return tfm(im.convert("RGB"))
```

改后：

```python
def _load_one(path, tfm, src_size=None):
    """读一张图并做确定性变换。

    src_size 给定时，先用 JPEG 的 draft 让 libjpeg 按 1/N 尺度解码（只对 JPEG 有效），
    把解码成本从「原图像素」降到「够用就行」——这是 100ms 预算的关键。

    ⚠ 必须保证 predict.py 与 cost.py 传同一个 src_size：
       同一个数值 → 同一串像素 → 同一组概率（规则第 7 条的一致性核验靠这个）。
    """
    with Image.open(path) as im:
        if src_size:
            # draft 只在 JPEG 上生效，PNG 会静默忽略（不影响正确性）
            im.draft("RGB", (src_size, src_size))
        return tfm(im.convert("RGB"))
```

然后把 `predict_paths` 里那行 `batch = torch.stack([_load_one(p, tfm) for p in chunk])...`
改成传 `src_size=PREP_SIZE`（从 config 导入，即 600）。

**为什么用 600 而不是 448**：训练时模型看的是 600→448（两次重采样），
如果推理走 764→448（一次），重采样链就和训练不一致了，白掉分。
所以 draft 到「刚好 ≥600」再走 600→448，既省解码又和训练严格对齐。

### 2.4 【新增】`tools/bench_inference.py`：三档计时（约 60 行）

cost.py 需要 submission.csv 才能跑，P0 阶段还没有。所以写个只管计时的精简版：

```python
"""三档分辨率计时：不比对 submission，只测「原图 → 概率」的端到端墙钟时间。"""
import argparse, time, os
from collections import defaultdict
import numpy as np, torch
from PIL import Image

from common import read_split_csv
from config import DATA_ROOT, PREP_SIZE, USE_AMP
from inference import load_model_for_inference, predict_one_path
from models import build_model

def build_dummy(backbone, img_size, device):
    """没有 ckpt 时构造一个同结构的随机模型（计时只关心结构，不关心权重）。"""
    m = build_model(backbone, pretrained=False).eval().to(device)
    return m, {"backbone": backbone, "img_size": img_size}

def main():
    p = argparse.ArgumentParser()
    p.add_argument("--sizes", nargs="+", type=int, default=[384, 448, 512])
    p.add_argument("--backbone", default="convnext_base")
    p.add_argument("--n", type=int, default=100)
    p.add_argument("--ckpt", default=None, help="给了就用真实权重，否则用随机权重")
    p.add_argument("--warmup", type=int, default=5)
    args = p.parse_args()

    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    use_amp = USE_AMP and device.type == "cuda"
    rows = read_split_csv("test")[:args.n]
    paths = [os.path.join(DATA_ROOT, "test", r["Subject_id"], r["Study_id"],
                          r["Dicom_id"] + ".jpg") for r in rows]
    print(f"计时图 {len(paths)} 张（原图）| 设备 {device} | AMP {use_amp}\n")

    for size in args.sizes:
        if args.ckpt:
            model, meta = load_model_for_inference(args.ckpt, device, img_size=size)
        else:
            model, meta = build_dummy(args.backbone, size, device)
        for pth in paths[:args.warmup]:                       # 预热，不计入
            predict_one_path(model, pth, size, device, tta=False, use_amp=use_amp)
        if device.type == "cuda": torch.cuda.synchronize()

        ts = []
        for pth in paths:
            if device.type == "cuda": torch.cuda.synchronize()
            t0 = time.perf_counter()
            predict_one_path(model, pth, size, device, tta=False, use_amp=use_amp)
            if device.type == "cuda": torch.cuda.synchronize()
            ts.append((time.perf_counter() - t0) * 1000)
        ts = np.array(ts)
        print(f"{size}px  均值 {ts.mean():6.1f} ms | 中位 {np.median(ts):6.1f} | "
              f"p90 {np.percentile(ts,90):6.1f} | 折算 T4 {ts.mean()*3.5:.0f}~{ts.mean()*4:.0f} ms")
        del model
        if device.type == "cuda": torch.cuda.empty_cache()

if __name__ == "__main__":
    main()
```

跑法：


## 第 3 章　P1 自监督升级（D2）

### 3.1 为什么换 DINO（不换也行，但先看这个）

现在用的是 SimCLR，它的核心是「批内所有其他图片都是负样本」。问题是：
- 负样本要够多才有效 → batch 得拉到 4096 才接近论文效果，我们 4 卡最多 512
- 3 万张图 + batch 512，每次只能看到 1.7% 的数据当负样本 → 梯度信号很稀

DINO 换了个思路：**不用负样本，用一个「教师的输出分布」当目标**。
教师是学生的指数滑动平均（和 EMA 一个道理），标准做法是多裁剪（2 个全局视图 + 6 个局部视图）。
小数据集上它比 SimCLR 稳得多——这正是我们的处境。

**这不是必须做的**。如果 G1 判定 DINO 没赢，直接回退 SimCLR 20ep，把这一天挪给 P2。

### 3.2 【新增】`dino_pretrain.py`：结构规格

不要从零写，**复制 `ssl_pretrain.py` 再改这五处**：

| 位置 | 原（SimCLR） | 改为（DINO） |
|---|---|---|
| 模型 | `SimCLRModel`：encoder + 2 层 MLP 投影头 | 两套同结构：`student`（可训）+ `teacher`（`requires_grad=False`，从 student 深拷贝） |
| 教师权重 | 无 | 每个 step 后 `teacher = m*teacher + (1-m)*student`，`m` 从 0.99 线性升到 0.999 |
| 输出 | `F.normalize(...)` 后算 NT-Xent | 投影后接 **weight-normalized** 全连接到 65536 维（原型），输出 softmax(τ=0.1) 分布 |
| 损失 | `nt_xent` | 交叉熵 `-Σ p_teacher·log p_student`，**对 6 个局部视图各算一次，对 2 个全局视图取平均** |
| 防坍缩 | 不需要（负样本天然防） | **必须**：teacher 输出先做 centering（减滑动均值 `m=0.9`）+ sharpening；否则所有样本输出同一个向量，loss 会掉到 0 但特征全废 |

**最小可行版**（时间紧就做这个）：不做 65536 原型，改成 `out_dim=4096` 的普通 MLP + softmax，
全局视图 2 个、局部视图 4 个（局部 = `RandomResizedCrop(224, scale=(0.25,0.5))` 后 resize 到 224）。
效果略差但代码量省一半，足够验证「DINO 是否优于 SimCLR」这个二元问题。

**必须加的防呆**（这是上一轮 EMA 那个坑的教训）：
每轮打印 `教师更新 N 步`，`N` 必须等于「轮数 × 每轮步数」。数字不对 = 教师没更新 = 整个训练作废。

3. 每轮耗时与第 1 章记的 SimCLR 单轮时间同量级（差 2 倍以内）

## 第 4 章　P2 单折消融（D3-D4）

### 4.0 优先级调整（相对计划文档，我有改动，理由在下面）

原计划把「多 stage 融合」排第一，我改成 **A5(512) → A3a(多尺度裁剪) → A2(强增强) → A1(融合) → A4(排序损失)**。

**理由**：融合的作用是「把浅层细节捞回来」，而 512 分辨率是「根本不让细节丢掉」。
两者解决同一个问题，但 512 更直接。**如果 512 能过 G0，A1 的边际收益会明显缩水**，就不值得为它改三个文件。

### 4.1 【新增】`tools/bootstrap_ci.py`：判据工具（约 50 行）

**这是整套实验的地基**：没有它，你只能比较两个点估计，而在 859/2211 样本上点估计差 0.005 完全可能是噪声。

```python
"""配对 bootstrap：判断配置 B 是否真的比 A 好。

输入两个 npz（predict.py 产出，必须评估同一批行），对同一批样本重采样 2000 次，
算 AUC 差的 95% 置信区间。区间跨 0 = 没有证据。
"""
import argparse
import numpy as np

# 复用 common 里的聚合与 AUC，保证与训练时口径完全一致
from common import aggregate_by_study, macro_auc, read_split_csv, read_csv_path

def main():
    p = argparse.ArgumentParser()
    p.add_argument("--a", required=True, help="基线 npz")
    p.add_argument("--b", required=True, help="对照 npz")
    p.add_argument("--csv", default=None, help="评估行对应 CSV（K折验证用）")
    p.add_argument("--split", default="valid", choices=["valid", "train"])
    p.add_argument("--n", type=int, default=2000)
    args = p.parse_args()

    rows = read_csv_path(args.csv) if args.csv else read_split_csv(args.split)
    za, zb = np.load(args.a, allow_pickle=True), np.load(args.b, allow_pickle=True)
    assert (za["dicom_ids"] == zb["dicom_ids"]).all(), "两个 npz 的行顺序不一致，不能配对比较"

    # 按 study 聚合后取每个 study 的预测与标签
    sa, sp_a, sl = aggregate_by_study(rows, za["probs"])
    sb, sp_b, _  = aggregate_by_study(rows, zb["probs"])
    assert (sa == sb).all()
    n = len(sa)

    rng = np.random.default_rng(0)
    diffs = []
    for _ in range(args.n):
        idx = rng.integers(0, n, n)                     # 有放回重采样 study
        d = macro_auc(sl[idx], sp_b[idx]) - macro_auc(sl[idx], sp_a[idx])
        diffs.append(d)
    diffs = np.array(diffs)
    lo, hi = np.percentile(diffs, [2.5, 97.5])
    print(f"A: {macro_auc(sl, sp_a):.4f}   B: {macro_auc(sl, sp_b):.4f}   "
          f"Δ={macro_auc(sl, sp_b)-macro_auc(sl, sp_a):+.4f}")
    print(f"B−A 的 95% 区间: [{lo:+.4f}, {hi:+.4f}]  → "
          f"{'有证据' if (lo > 0 or hi < 0) else '无证据（跨 0）'}")

if __name__ == "__main__":
    main()
```

**注意**：`aggregate_by_study` 的参数名在各版本里可能是 `how=` 或 `agg=`，跑之前 `grep -n "def aggregate_by_study" -A6 common.py` 确认一次。

### 4.5 【改】A4 排序损失（风险最高，最后做）

在 `losses.py` 里加一个辅助项，`train.py` 里把 `criterion(logits, labels)` 换成
`focal_loss + lam * ranking_loss`（`lam=0.3` 起步）。

```python
def pairwise_ranking_loss(logits, labels, margin=0.0):
    """类别内 pairwise logistic loss：正样本的分数应高于负样本。

    直接优化 AUC 的排序目标，而 BCE/Focal 优化的是概率校准——两件事。
    罕见类正样本太少时这个差别尤其明显，所以它和 A3a 是互补的。
    """
    loss, cnt = logits.sum() * 0.0, 0
    for c in range(logits.size(1)):
        pos = logits[labels[:, c] > 0.5, c]
        neg = logits[labels[:, c] < 0.5, c]
        if len(pos) == 0 or len(neg) == 0:
            continue                      # 该 batch 没正样本，跳过（罕见类的常态）
        d = pos.unsqueeze(1) - neg.unsqueeze(0) - margin
        loss = loss + torch.nn.functional.softplus(-d).mean()
        cnt += 1
    return loss / max(1, cnt)
```

**风险提示**：batch=32 时，类 1（占比 2.95%）平均每 batch 只有 0.94 个正样本，
一半以上的 batch 会走 `continue`，梯度信号很断续。所以 A4 **最好和类别平衡采样一起做**，
而那又是一处新改动。**如果时间只够做一件事，不要选 A4。**

## 第 7 章　P4 蒸馏（D10-D11）

### 7.1 为什么必须用 OOF 软标签（**这一步做错就白干**）

想蒸馏 5 折集成，就得先有"教师对训练图的预测"。但**每个折模型都见过自己那 80% 的训练图**，
直接用它预测 → 教师在自己见过的图上给出过于自信的答案 → 学生学到的是"背答案"。

正确做法：**每一行训练图的软标签，只由没见过它的那个折模型提供** —— 这正是 OOF。
每行恰好有 1 个模型没见过它（fold_i 的 val 里那 20% 由 f_i 提供……反过来说，
fold_i 的训练行要由**其他折**提供）。

**精确规则**：行 r 在 fold_i 的 val 里 → 用 f_i 的预测作软标签。
因为 f_i 没在训练中见过 r。这样每行都拿到一个"干净"的教师答案。

### 7.2 【新增】`distill.py`：结构规格

复制 `train.py`，改三处：

| 项 | 改法 |
|---|---|
| 数据 | 训练集 = 全量 train（30344 行），每行带一个 10 维软标签（来自 OOF），存成 `.npz` |
| 损失 | `loss = 0.5 * KL(sigmoid(student/T) ‖ soft_target/T) * T² + 0.5 * hard_focal_loss`，`T=2` |
| 起点 | `--ssl runs/ssl/dino200.pth` 或不带（用 ImageNet 起点），与主线一致 |

```bash
python distill.py --epochs 14 --img-size 512 --ssl runs/ssl/dino200.pth \
                  --soft runs/oof_soft.npz --out runs/distill
```

| 结果 | 决定 |
|---|---|
| 蒸馏模型 OOF ≥ 集成 −0.003 | **采用蒸馏模型**（单模型 175MB fp16 / 334MB fp32，合规） |
| 蒸馏掉点更多 | 放弃蒸馏，直接用 5 折里最好的那一折模型 |

> 蒸馏的价值不在"提分"，在"把 5 个模型的判断塞进 1 个模型"。所以判据是"别掉太多"，
> 不是"必须涨"。

## 第 10 章　术语与公式速查

| 词 | 一句话解释 |
|---|---|
| **Macro AUC** | 先对 10 个类别各算一个 AUC（0.5=瞎猜，1=完美），再**简单平均**。所以罕见类和常见类权重一样 |
| **AUC** | 随机取一个正样本和一个负样本，模型给正样本打分更高的概率。**只看排序，不看绝对值** |
| **study 聚合** | 一次检查可能有多张图，模型逐图出概率，再按 study 取平均，得到一个 study 的概率 |
| **pos_weight** | 给罕见类加权，让 loss 更在乎它们。本方案封顶 10（effective number 公式算出类 1 应该是 32.9，砍到 10 是防止过拟合） |
| **EMA** | 维护一份"训练权重的高光滑版本"，decay=0.9997 表示每步只吸收 0.03% 的新权重。**必须每步更新** |
| **soup** | 把多个模型的权重直接平均成一个。只消种子抖动，不产生互补增益 |
| **真集成** | 多个模型分别预测再平均。有互补增益，但体积 ×N |
| **蒸馏** | 让学生模型去拟合教师（集成）的输出分布，把 N 个模型的判断压进 1 个 |
| **OOF** | Out-of-Fold：每一行训练数据的预测，都由没见过它的那个模型给出。无泄漏，可用作训练信号和评估 |
| **draft** | PIL 的 JPEG 解码降采样开关，让 libjpeg 按 1/N 尺度解码，省 90% 以上解码时间 |
| **固定换算** | 平台分 ≈ valid − k，k 当前实测 0.0295。每次提交后更新 k |
