# 找 Kaggle 方案时的检查清单

> 用途：在 Kaggle（Grand X-Ray Slam）上搜索开源方案，判断「能不能改成我们这份赛题」。
> 依据：`规则.md`（第 1/2/5/6/7/8/11 条 + 附录 A）、`规则补充.md`（二~十）、`赛题说明.md`。
> 配套脚本：`tools/screen_solution.py`（自动化体检，见第 6 节）。
> 记录时间：2026-10-30

---

## 0. 先记住一句话

**这个 Kaggle 赛的前排方案，绝大多数建在「医学预训练权重」这块地基上；而我们的规则第 1 条恰好禁止医学预训练权重。
地基不合规，楼上怎么装修都没用。**

所以看到 Div A / Div B 前十名的方案，默认判断是：**能借思路，不能借代码**。
真正能直接搬的，是那些「用 ImageNet 骨干 + 普通训练技巧」的中游方案——分数不一定最高，但移植成本最低。

---

## 1. 改动是分层的：先判断它属于哪一层，再决定投多少时间

| 层次 | 典型改动 | 成本 | 危险度 | 判断 |
|---|---|---|---|---|
| L1 字符串级 | 改路径、改列名、改文件名 | 10 分钟 | 低，改错立刻报错 | 放心改 |
| L2 逻辑级 | 提交格式、标签映射、图→study 聚合 | 半天 | **高，改错了不报错、分数悄悄掉** | 必须写自检 |
| L3 结构级 | 换骨干、换分辨率、拆依赖 | 1~2 天 | 中，有报错可循 | 按预算决定 |
| L4 地基级 | 预训练权重来源、外部数据 | **无法改** | 致命 | 直接放弃整份代码 |

**关键认知**：L1 和 L2 是「你以为很简单」的部分。
14 类改 10 类看起来只是删 4 列，但 Kaggle 的列是**字母序**、我们的类别 id 是**语义序**，
如果习惯性地写 `preds[:, :10]` 或按位置重排，10 个类会整体错位——**AUC 掉到 0.5 附近，但程序一声不响地跑完了**。
这是整份清单里最容易踩、最难查的坑。

---

## 2. 红线：命中就别改了，直接换项目

以下五类**不能通过修改代码修复**，因为违反的是「方案成立的前提」，不是「实现细节」。

### W1 医学影像预训练权重（规则第 1 条 + 补充二）

判定依据是**预训练主数据集**，不是模型结构、不是作者单位、不是"它在 ImageNet 上也 pretrain 过"。

代码里常见的藏身处：

| 写法 | 实际是什么 | 判定 |
|---|---|---|
| `EVA-X` / `evax` | 在 MIMIC-CXR 上预训练 | ❌ 不合规 |
| `CheXFound` / `GLoRIA` | CheXpert 图文预训练 | ❌ 不合规 |
| `torchxrayvision` / `xrv` | DenseNet121 的 CheXpert 权重 | ❌ 不合规 |
| `timm.create_model(..., pretrained=True)` 但模型名带 `radimagenet` | RadImageNet 是医学影像集 | ❌ 不合规 |
| `microsoft/rad-dino`、`google/cxr-foundation`、`StanfordAIMI/CheXagent` | 医学自监督/多模态权重 | ❌ 不合规 |
| `RETFound` 及其衍生 | 眼底医学图像 | ❌ 明确点名 |
| `MedSAM`、`MedicalNet`、病理 `UNI/CONCH` | 医学分割/病理预训练 | ❌ 不合规 |
| `torchvision.models.convnext_base(weights='IMAGENET1K_V1')` | ImageNet-1k | ✅ 合规 |
| 随机初始化 | 无预训练 | ✅ 合规 |
| 合规权重 + 官方训练集自监督续训 | 补充四明确允许 | ✅ 合规（需申报） |

**为什么不能改**：把 EVA-X 换成 ConvNeXt 之后，这个方案里所有针对 EVA-X 的调参（层间学习率、输入尺寸 448、
归一化系数、冻结策略、6 epoch 的 schedule）全部失效。你得到的是「一份别人的超参 + 一个自己的模型」，
它既不能证明有效，也没有任何复用价值——不如从我们自己的 `baseline1/` 起手。

**两个附加门槛**（很多人只看"是不是医学"就放过了）：

1. **许可证不能是 NC**（非商业）。规则第 1 条写明「采用 NC 类许可证……不予接受」。
   即使是纯 ImageNet 权重，若上游是 CC-BY-NC，也不合规。
2. **不能是 gated 模型**（需登录/申请才能下载）。附录 A 要求「公网可直接访问、无需登录」。
   Kaggle 方案里大量的 `!gdown --folder https://drive.google.com/...` 就是典型违规：
   权重存在网盘里，无法提供稳定直链、无法核验 SHA-256、离线容器也下不到。

### W2 运行期联网下载权重

特征：`!pip install`、`!git clone`、`!wget`、`!gdown`、`torch.hub.load(...)`、`requests.get(...pth)`。

三重违规：复赛容器离线（跑不起来）+ 权重来源不可申报 + 往往就是 W1 的医学权重。
**处置**：权重必须提前落盘到 `pretrain_model/`，并在申报表 A1~A6 写清名称、直链、许可证全文、上游数据、SHA-256。

### W3 外部医学数据（规则第 2 条 + 补充五）

包括但不限于：用 NIH ChestX-ray14 / CheXpert / MIMIC-CXR / PadChest / VinDr 做预训练、续训、
伪标签、微调；**也包括「只用它算 mean/std」和「只用无标签图做自监督」**——补充五写明「是否带标签不改变数据属性判定」。

隐蔽点：`A.Normalize(mean=[0.5056, 0.5056, 0.5056], std=[0.252, 0.252, 0.252])`
这种单通道灰度系数，看着像"通用常数"，实际是别人在 CheXpert 上统计出来的。
ImageNet 的标准三通道 `[0.485,0.456,0.406]/[0.229,0.224,0.225]` 可以用（随权重自带），其余数值要能说明出处。

### W4 蒸馏教师是医学模型（补充三）

`教师 = EVA-X，学生 = ImageNet 骨干` 这种「洗权重」的做法**明确禁止**，
且补充三（四）写明「即使教师不参与最终推理、学生未超 500MB，亦因违反第 1 条而禁止」。

### W5 测试集参与任何决策（规则第 5 条）

Kaggle 有 public/private LB 实时反馈、提交次数也更宽松，方案里普遍存在「看 LB 选 ckpt / 选 TTA 组合 / 选阈值」。
我们每天只有 2 次提交、几乎没有试错空间，**这类"经验"一条都不能搬**：
所有选择必须在自建 patient 级验证集上定死，然后一次性提交。

## 3. 必须改的适配点（漏改不会报错，只会静默掉分）

对照表——左边是 Kaggle 原版实测事实，右边是我们的赛题：

| # | 维度 | Kaggle（Grand X-Ray Slam，实测其公开方案） | 本地赛 | 漏改后果 |
|---|---|---|---|---|
| A1 | 标签数量 | 14 类（MIMIC 口径） | 10 类 | 输出维度不匹配 / 多出的 4 类无意义 |
| A2 | 标签顺序 | **字母序**：Atelectasis, Cardiomegaly, …, Support Devices | **语义序 id 1~10**：1 纵隔心影增大 … 10 无异常 | **整体错位，AUC≈0.5** |
| A3 | 提交形态 | 宽表：`Image_name` + 14 列概率，一行一图 | 长表：`Subject_id, Study_id, Predict_class, Probability`，一行一类 | 平台解析失败 |
| A4 | 评测粒度 | **图像级**（按 Image_name 评） | **study 级**（按 Study_id 评） | 多图 study 没聚合，白丢分 |
| A5 | 数据路径 | `/kaggle/input/...` 平铺文件名 | `cxr_first/{split}/subject_x/study_y/pic_z.jpg` 三层 | 直接崩 |
| A6 | 数据划分 | Div A / Div B 两套独立数据 | 单套 train/valid/test，study id 区间切分 | 逻辑对不上 |
| A7 | 输出语义 | 概率（部分方案按 0.5 截断成二值） | 只要概率，Macro AUC 与阈值无关 | 做阈值调优=白费 |
| A8 | 依赖 | notebook 里随时 `pip install fvcore / open_clip_torch / timm` | 只保证 torch 2.10 + torchvision 0.25，且离线 | 推理崩 |
| A9 | 体积/时延 | 无硬约束 | 权重 ≤500MB、单张端到端 ≤100ms（T4） | 复赛成绩不予认定 |
| A10 | 提交次数 | 通常每日多次 + public LB 实时反馈，可反复试错 | 每天 2 次，且无有效反馈 | 拿名额试错=浪费 |

### A2 专项：14→10 的正确映射（背下来）

| 本地 id | 名称 | Kaggle 列名 |
|---|---|---|
| 1 | 纵隔心影增大 | Enlarged Cardiomediastinum |
| 2 | 气胸 | Pneumothorax |
| 3 | 肺部实变 | Consolidation |
| 4 | 肺炎 | Pneumonia |
| 5 | 肺水肿 | Edema |
| 6 | 心影扩大 | Cardiomegaly |
| 7 | 肺不张 | Atelectasis |
| 8 | 肺部阴影 | Lung Opacity |
| 9 | 胸腔积液 | Pleural Effusion |
| 10 | 无异常发现 | No Finding |

**要从 14 类里删掉的 4 类**：`Fracture`、`Lung Lesion`、`Pleural Other`、`Support Devices`。
（`Support Devices` 在题面字段说明里提过，但 CSV 里没有这一列，别去找。）

正确写法必须是「按名字取列」：
```python
NAME2ID = {"Enlarged Cardiomediastinum":1, "Pneumothorax":2, "Consolidation":3, ...}
prob10 = np.stack([prob14[:, cols.index(n)] for n in NAME2ID], axis=1)  # 不是 [:10]，不是排序后切片
```
写完必须验证一次：在官方 valid 上算每类正样本数，和已知的
`10:12649 / 8:6703 / 9:6637 / 7:5649 / 6:5590 / 5:3220 / 4:2293 / 3:1265 / 2:1238 / 1:894`（按图行）
对得上，才说明映射没串。

### A4 专项：study 级聚合

Kaggle 那份方案的提交单位是 `Image_name`（单图），所以**它根本没有聚合这一步**——
这是移植时最容易整段漏掉的逻辑，因为它「不存在」，你搜代码搜不到。
我们必须自己补：同一 Study_id 的多张图取均值（补充七明确：确定性聚合 = 允许，性质同 TTA），
聚合方式（mean / max / 按 ViewPosition 加权）是可调超参，须在并入验证集前定死。

### A8 专项：依赖降级对照

| Kaggle 常用 | 替换成 |
|---|---|
| `timm.create_model` | `torchvision.models.*` |
| `albumentations` | `torchvision.transforms.v2` |
| `cv2.imread/resize` | `PIL.Image` |
| `sklearn.metrics.roc_auc_score` | numpy 手写（baseline1 已实现） |
| `fvcore`、`open_clip` | 直接删 |
| `pandas` | 可用（但提交层建议纯 csv 模块，避免版本坑） |

## 4. 六个「看起来合规、其实不合规」的伪装

1. **「我们只在 ImageNet 上预训练」**——但 `load_state_dict` 加载的文件名是 `eva_x_base.pth`。
   看代码不如看权重文件名和 `model_card`。
2. **「这个模型也在 ImageNet 上跑过」**——混入少量医学数据不违规（规则第 1 条明确），
   但**主数据集**是医学就不行。判据是 model card 写的 pretrain dataset，不是它能不能跑 ImageNet。
3. **「我只用它的归一化系数」**——外部医学数据统计量，违规（等同外部数据）。
4. **「我只用无标签的 MIMIC 图做自监督」**——补充五：无标签也违规。
5. **「教师模型不进最终推理，所以不算」**——补充三（四）：仍然禁止。
6. **「许可证是 CC-BY-NC，但我们不商用」**——规则第 1 条：NC 类一律不接受，无例外条款。

## 5. 哪些东西可以放心拿走

红线是「权重和数据」，不是「知识」。以下模块与数据无关，直接抄没问题：

- **损失函数**：WeightedFocalBCE（effective-number 算 pos_weight，β=0.9999）→ 只需按我们的 10 类正样本数重算权重
- **训练技巧**：EMA（0.9997）、layer-wise LR、cosine 预热、AMP、checkpoint 平均（相邻两 epoch 权重平均）
- **增强配方**：几何 + 光度 + 遮挡（CoarseDropout），推理时全关
- **TTA**：原图 + hflip + 多尺度 + 亮度，6 种取平均（注意时延预算）
- **预处理缓存**：先把大图统一缩到 600² 落盘成 jpg，训练时再 resize 到目标尺寸——省 I/O，且合规
- **推理工程**：按 batch=1 串行、`torch.no_grad()`、`model.eval()`、固定 seed 的确定性写法

这些在我们的 `baseline1/` 里已经有合规版本（`losses.py`、`ema.py`、`train.py`、`predict.py`、`preprocess.py`），
所以从 Kaggle 方案里真正值得抄的，主要是**超参直觉**和**训练稳定性技巧**，而不是代码本身。

## 6. 三分钟体检流程（拿到任何方案先跑一遍）

```bash
python3 tools/screen_solution.py <方案目录或.ipynb>
# 只看结论：
python3 tools/screen_solution.py <方案目录> --quiet
```

脚本会按规则库扫 `.py` / `.ipynb` 的代码单元格（自动跳过输出和中文注释），输出三档：
`🔴 红线` / `🟡 适配` / 提示，并给出「为什么违规 + 怎么办」。

**实测对照**（同一脚本跑两份代码）：

| 对象 | 结果 | 说明 |
|---|---|---|
| `Grand-X-Ray-Slam-competition/` | `W1🔴` + 7 项适配 | 医学权重红线，符合预期 |
| `baseline1/`（我们的合规实现） | 0 红线，仅黄色适配提示 | 说明脚本不瞎报 |

不动手的部分仍需人工确认（脚本判断不了）：
1. 打开权重文件名 / model card，确认 pretrain dataset（W1 的最终判据）
2. 打开 `sample_submission`，确认提交列名与粒度（A3/A4）
3. 数一遍 TTA 次数 × 单模型时延，估算是否 ≤100ms（A9）

## 7. 移植完的自检清单（8 条，缺一条都别提交）

1. 输出是 `1414 × 10 = 14140` 行，Study_id 无缺失、无重复
2. `Study_id` 按字符串读，7 位前导零没丢（`0000001` 不是 `1`）
3. 每类概率都在 `[0,1]`，保留 6 位小数，**没有做 0.5 截断**
4. 10 个类别 id 与病名映射正确（用正样本数反查）
5. 同一 study 多图已聚合，聚合方式写进文档
6. 训练/推理的图像尺寸与归一化完全一致
7. `cost.py` 与 `predict.py` 调用同一份推理函数，100 张一致性 0 张不符
8. 权重目录解压后 ≤500MB（含 config / 归一化系数 / 类别表）

## 8. 值不值得立项：一张打分卡

给每个候选方案打分，总分 100：

| 维度 | 分值 | 判据 |
|---|---|---|
| 合规性 | 40 | 无红线得 40；有一项红线直接 0 分（只借思路） |
| 可移植性 | 25 | 依赖少、无 notebook 魔法、有独立 `model.py`/`inference.py` 得高分 |
| 预期收益 | 20 | 是否带来我们 `baseline1/` 里没有的东西（新增强/新损失/新聚合策略） |
| 可验证性 | 15 | 能否在小样本上跑通并给出 per-class AUC 对比 |

- **≥70 分**：值得投入 1~2 天移植
- **40~70 分**：只抄特定模块（损失/增强/TTA）
- **<40 分或命中红线**：记录思路，关掉页面

## 9. 一句话总结

> 找方案时先看**权重从哪来**（决定生死），再看**提交怎么出**（决定分数），最后才看**模型多强**。
> 顺序反了，就会花两天时间把一份不合规的方案改到能跑，然后发现它连提交都交不上去。
